## Local plan simulation

To preview a plan in local development, set `SIMULATE_PLAN` in `.env.local` to `standard`, `pro`, `business`, or `pro_max`. Values are case-insensitive, and spaces, hyphens, and underscores are normalized (for example, `Pro Max` or `pro-max`). Restart `npm run dev` after every change. The simulated plan takes precedence over both the creator entitlement and a Stripe subscription, and Stripe checkout is disabled while simulation is active. Never set this variable in Vercel or production: it overrides the plan for every authenticated account.

## Creator account access

Set `CREATOR_EMAIL` to the verified email address of the creator's Flux account in `.env.local` for local development and in the Vercel project's **Settings → Environment Variables** for each environment that should grant access. Redeploy after changing the Vercel variable. Keep this variable server-side; do not rename it to `NEXT_PUBLIC_CREATOR_EMAIL`.

```env
CREATOR_EMAIL=verified-account@example.com
```

The matching authenticated account receives the Pro Max entitlement, including all four plans' features and quotas, without a Stripe subscription. Other accounts continue to use the normal subscription and Stripe checkout flow. The configured email must be confirmed by Supabase Auth.

## Optional Gmail connection

The optional Gmail connection remains available in Settings. AI follow-ups for quotes, invoices, and customers are sent through Resend instead. Gmail OAuth requires the Gmail API to be enabled in Google Cloud and the following server-side environment variables:

- `GOOGLE_CLIENT_ID` and `GOOGLE_CLIENT_SECRET`
- `GOOGLE_REDIRECT_URI`, matching the Google OAuth callback URL: `https://<your-domain>/api/email/gmail/callback`
- `GMAIL_TOKEN_ENCRYPTION_KEY`: a base64-encoded 32-byte key
- `GMAIL_OAUTH_STATE_SECRET`: a random secret of at least 32 characters
- `SUPABASE_SERVICE_ROLE_KEY` and the existing Supabase URL/key configuration

Generate the two Gmail-specific secrets with Node.js:

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

Apply `supabase/migrations/20261122000300_create_email_connections.sql` to the Supabase project before using the integration. Refresh tokens are encrypted server-side and are not readable through client-side Supabase access.

## AI follow-ups with Resend

Follow-up drafts for quotes, invoices, and customers are generated by OpenAI. After the user reviews and confirms a draft, Flux sends it through Resend. Configure these server-side environment variables:

- `RESEND_API_KEY`
- `RESEND_FROM_EMAIL`, using a sender address or display name on a domain verified with Resend (for example, `Flux <billing@example.com>`)
- `OPENAI_API_KEY`; `OPENAI_MODEL` is optional and defaults to `gpt-4o-mini`

AI follow-up generation and sending require an active Standard subscription or higher, or the configured creator account. Invoice reminder status is saved with the app's local invoice data.

In Vercel, add the Resend variables under **Project → Settings → Environment Variables** for Production (and Preview/Development if needed), then redeploy for the changes to take effect.
